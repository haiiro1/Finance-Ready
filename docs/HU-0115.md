# HU-0115 - Aplicar el modelo visual a Configuracion

## Objetivo

Aplicar en `/configuracion` el patron visual de HU-0109 para anticipar preferencias de cuenta, moneda, categorias y seguridad sin exponer controles no funcionales como si persistieran cambios.

## Criterios de aceptacion

- [ ] `/configuracion` usa la composicion y tokens del shell.
- [ ] La vista organiza las futuras areas de cuenta, preferencias, moneda, categorias y seguridad con jerarquia clara.
- [ ] Ningun switch, selector o boton aparenta guardar cambios si no existe implementacion real.
- [ ] Danger queda reservado para acciones destructivas reales y no se usa decorativamente.
- [ ] La vista funciona en mobile, desktop, claro y oscuro.
- [ ] No se implementa persistencia, formularios funcionales ni endpoints.

## Paso 2 - Implementacion visual

1. Reutilizar encabezado y estado vacio compartidos.
2. Agrupar visualmente las futuras secciones sin renderizar formularios engañosos.
3. Mantener el selector de tema existente en el shell; no duplicarlo sin una decision funcional.
4. No permitir que controles disabled parezcan interactivos.
