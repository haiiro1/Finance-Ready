# HU-0007 - Configurar variables de entorno

## Objetivo

Centralizar configuracion sensible para facilitar despliegues, seguridad y configuracion por entorno.

## Criterios de aceptacion

- [ ] Existe `.env.example`
- [ ] Backend carga variables correctamente
- [ ] Frontend carga variables correctamente
- [ ] No existen secretos hardcodeados

## Paso 1 - Inspeccion inicial

La IA ejecutora debe revisar los siguientes archivos:

```text
Backend/.env.example
Backend/.env
Backend/app/core/config.py
Backend/app/main.py
docker-compose.yml
frontend/package.json
frontend/apps/shell/vite.config.ts
frontend/apps/shell/src/*
frontend/apps/shell/.env.example
frontend/apps/shell/.env
```

Buscar posibles secretos o configuracion sensible hardcodeada:

```powershell
git grep -n "password\|secret\|token\|key\|DATABASE_URL\|POSTGRES_PASSWORD\|VITE_" -- . ":(exclude)frontend/node_modules" ":(exclude)Backend/.venv"
```

## Paso 2 - Backend

Validar que exista:

```text
Backend/.env.example
```

Debe contener valores seguros de desarrollo:

```env
APP_NAME=Finance Ready API
APP_ENV=local
API_PREFIX=/api/v1
CORS_ORIGINS=http://localhost:5173
DATABASE_URL=postgresql+psycopg://finance:finance@localhost:5432/finance_ready
```

Revisar:

```text
Backend/app/core/config.py
```

Debe cumplir:

- Usa `BaseSettings`.
- Carga variables desde `.env`.
- Permite override desde variables reales del entorno.
- Expone `database_url`, `api_prefix`, `cors_origins` y `app_env`.
- No contiene secretos productivos hardcodeados.

## Paso 3 - Frontend

Crear o validar:

```text
frontend/apps/shell/.env.example
```

Contenido esperado:

```env
VITE_API_URL=http://localhost:8000/api/v1
```

Crear o validar una configuracion frontend centralizada, por ejemplo:

```text
frontend/apps/shell/src/config.ts
```

Contenido sugerido:

```ts
export const appConfig = {
  apiUrl: import.meta.env.VITE_API_URL ?? 'http://localhost:8000/api/v1',
}
```

Luego reemplazar cualquier URL API hardcodeada por:

```ts
appConfig.apiUrl
```

## Paso 4 - Docker Compose

Revisar:

```text
docker-compose.yml
```

Debe pasar variables al backend:

```yaml
APP_NAME: Finance Ready API
APP_ENV: docker
API_PREFIX: /api/v1
CORS_ORIGINS: http://localhost:5173
DATABASE_URL: postgresql+psycopg://finance:finance@postgres:5432/finance_ready
```

Debe pasar variables al frontend:

```yaml
VITE_API_URL: http://localhost:8000/api/v1
```

Si se quiere mejorar la configuracion raiz, crear:

```text
.env.example
```

Contenido sugerido:

```env
POSTGRES_USER=finance
POSTGRES_PASSWORD=finance
POSTGRES_DB=finance_ready
POSTGRES_PORT=5432
BACKEND_PORT=8000
FRONTEND_PORT=5173
VITE_API_URL=http://localhost:8000/api/v1
```

## Paso 5 - Documentacion

Actualizar `README.md` con una seccion:

```text
Variables de entorno
```

Debe explicar:

- Copiar `Backend/.env.example` a `Backend/.env`.
- Copiar `frontend/apps/shell/.env.example` a `frontend/apps/shell/.env`.
- Docker Compose puede usar variables desde `.env` raiz.
- No se deben commitear secretos reales.

## Paso 6 - Validacion

Backend:

```powershell
cd F:\Code\Finance-Ready\Backend
uv run ruff check .
uv run pytest
```

Frontend:

```powershell
cd F:\Code\Finance-Ready\frontend
pnpm.cmd lint
pnpm.cmd build
```

Docker Compose:

```powershell
cd F:\Code\Finance-Ready
docker compose config
```

Opcional si no hay conflicto de puertos:

```powershell
docker compose up -d --build
docker compose ps
```

## Cierre de HU

Marcar la HU como completa solo si:

- Existe `Backend/.env.example`.
- Existe `frontend/apps/shell/.env.example`.
- Backend carga configuracion desde entorno o `.env`.
- Frontend usa `VITE_API_URL`.
- `docker-compose.yml` no contiene secretos productivos.
- No hay tokens, claves privadas, passwords reales ni URLs sensibles hardcodeadas.
- Las validaciones pasan o el bloqueo externo queda documentado.

## Riesgo residual

La credencial `finance/finance` es aceptable solo como credencial local de desarrollo.

Para despliegues reales, las credenciales deben venir desde variables externas, secretos del entorno o un secret manager.
